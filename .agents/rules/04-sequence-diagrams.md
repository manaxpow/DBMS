# Sequence Diagrams

## Objective

Describe runtime interactions.

One sequence diagram represents one scenario.

---

## Input

Approved Simple Class Diagram.

---

## Required

Include

- Actor
- Participants
- Message Flow
- Alternative Flow
- Error Flow
- Return Value

---

## Rules

Only use participants that already exist.

Never invent a new participant.

---

## Discover

Record

Method Candidates

State Candidates

Do not update the class diagram yet.

---

## Scenarios

At minimum

- Happy Path
- Failure Path
